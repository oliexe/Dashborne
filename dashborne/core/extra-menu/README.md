# Extra menu

Dashborne's core menu adds a **star icon** at the bottom right of the official
dashboard. It opens a separate Settings-style screen with a scrollable list
on the left and the selected extension's description and **Open** button on
the right. The layout matches stock Settings: five 75-pixel category rows,
15-pixel gaps, a 480-pixel left column, and a 1000-pixel content panel. The menu
uses the installed app's graphics for category states, the content background,
blue action button and Back arrow. Typography and Back placement match
the stock screen. The vertical **Tweaks** label and star icons are original
assets generated by `icons.py`. Drag the category list to scroll. **Back** returns
to the dashboard; closing an extension window returns to Extra.

The menu is linked into `libdashborne.so` and starts before selected plugins.
Its layout and icons live in `Dashborne/assets/extra-menu` on the card.
Only enabled plugins register entries; an empty menu explains how to add them.
Contrast remains in stock Settings as **\* Contrast**. Screen Mirroring opens from Extra.

## Add an entry

During your extension's `activate`, after preparing its window:

```c
if (!host->register_extra ||
    host->register_extra(host, "viewer", "My extension",
                         "A short description of this page.", open_my_window))
    return -1;
```

The callback runs on the UI thread. Use the extension's own callback; entry IDs
are unique within that extension. Titles allow 63 UTF-8 bytes, descriptions 127,
and the registry accepts up to 64 entries across enabled plugins. It lists them
in registration order. The host copies labels and removes callbacks before unloading
the owner, including when activation rolls back. Tokens are never reused in a
process, so a stale selection cannot open a different plugin.

## Implementation

`dashboard.json` is a guarded additive patch for the installed 6.11.2 dashboard.
The loader composes its button with selected layout patches, then starts the menu
before user extensions. The core hooks only the dashboard click callback,
delegating every other control to the previous handler. Before installing the
hook, the core checks app/runtime fingerprints and the expected callback.

The menu uses a native Activity with a resident factory trampoline, an original
SD layout and the runtime's scrollable list. The host registry is independent of
the menu Activity and checks registration ownership and lifecycle. A live or
queued menu prevents core shutdown. Cleanup restores dashboard hooks
in reverse order. These changes last for the Dashborne session.

```sh
uv run --with resvg-py==0.5.0 python dashborne/core/extra-menu/icons.py
python3 dashborne/core/extra-menu/generate.py
sh dashborne/core/extra-menu/test.sh
sh dashborne/extensions/test.sh
sh dashborne/test.sh
DASHBORNE_CC=/opt/homebrew/opt/llvm/bin/clang \
DASHBORNE_LD=/opt/homebrew/opt/lld/bin/ld.lld sh dashborne/build.sh
```

Host tests cover empty and 64-entry menus, selection and return, duplicate
opens, cleanup while a window is live, stale tokens, rollback, owner namespaces
and composition with selected patches. We also applied the dashboard patch to
the device layout and checked that it preserved the original controls. On
the DASH, the user confirmed the stock-style menu, opening Screen Mirroring and
returning to Extra. Deployment checks compared uploaded files with read-back
copies, preserved settings, and confirmed that configuration and ADB returned
after restarting the loader.
